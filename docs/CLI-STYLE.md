# CLI documentation policy

## Standard and scope

The writing standard is [ASD-STE100 Issue 9](https://www.asd-ste100.org/STE_downloads.html), dated 2025-01-15.
The source PDF supplies both the writing rules and the dictionary.
The repository does not redistribute that dictionary.

The controlled scope consists of:

- `CLI.md`: procedures and behavior.
- `CLI-REFERENCE.md`: command names, options, limits, and API mapping.
- `CLI-TERMS.md`: technical noun and verb definitions.
- `CLI-VERIFICATION.md`: results and verification limits.
- `RENTAL-CLI.md`: procedures and limits for the offline rental preview.
- `CLI-WRITING.md`: shared message rules and rental technical terms.
- Terminal help generated by the CLI command registry.

Code blocks, API paths, diagnostic labels, and JSON field names keep their exact application text.
Argument errors use fixed complete sentences without argument values or private paths.
Historical review records and Go API design notes are outside this operator documentation scope.

## Authoring rules

1. Use approved dictionary words with their approved meanings and parts of speech.
2. Use the term list for subject terms that the dictionary does not supply.
3. Use one term for each defined item.
4. Use American English spelling.
5. Write each procedure step in the imperative form.
6. Put the condition before the instruction when the condition affects the action.
7. Give one action in each procedure sentence.
8. Use no more than 20 words in a procedure sentence.
9. Use no more than 25 words in a descriptive sentence.
10. Use no more than six sentences in a paragraph.
11. Use active voice unless passive voice is necessary in a descriptive sentence.
12. Put instructions and limits outside information-only notes.
13. Use noun groups with no more than three words, except full official names.

## Documentation checks

The local suite compares the documented commands and options with the executable command registry.
It also examines prose sentence length, paragraph length, contractions, and procedure structure.
These checks do not show approved meanings, parts of speech, or full STE compliance.

1. Start the documentation checks:

   ```sh
   go test -run '^TestCLIDocumentation' ./internal/cli
   ```

2. Examine procedure actions, conditions, vocabulary, and term use against Issue 9.
3. Read every command example with the executable help.
4. Record the verification boundary in `CLI-VERIFICATION.md`.

Automated checks and editorial review apply the standard to this documentation.
This record does not include external certification or independent language review.
