## Root cause, independently repeated before changes

The unchanged current `JSONable` walker first honors `BankAccount` / `BankCard` / `BankPortfolio.MarshalJSON`. Those library-owned methods encode a typed snapshot with the ordinary encoder. The walker then decodes the document into untyped maps and strings and applies its **display** PAN policy. Typed Money becomes an amount-shaped string, losing the only valid reason not to mask Luhn-valid amounts. The raw-snapshot path retains Money, but treats literal account identifiers as display strings. Separately, the three ordinary entity marshalers allow the encoder to replace original invalid native UTF-8 with U+FFFD before any later document validation can detect the identity loss.

The exact archived probes were copied without edits into an immutable-dependency replay. `original-current-red.jsonl` records exit 1, four failing ordinary tests and 13 failing subtests (ten amount container seams and three owned marshalers), with two passing control tests and no setup/build failure.

## Scoped architecture

1. Admit **only exact library-owned native financial layouts** to the provenance boundary. Mark their source identity/code/date fields explicitly as literal text in their native schema, rather than guessing from an untyped JSON key named `id` or `amount`. Generic display strings, unknown native layouts and foreign custom JSON remain subject to the display policy. Existing parsed display labels remain PAN-safe; native generic display-label controls continue to mask.
2. Extract only a library-owned entity's copied `Snapshot` / `Raw` through a closed concrete-type boundary, before its compatibility marshaler can erase Money. No requester, binding, credential implementation or private graph is reflected over. Foreign wrappers that embed an entity do not inherit this admission and their redactors remain authoritative.
3. Use per-call, encoder-reached typed hooks and JSON Pointer provenance for streaming delegation and official `ErrUnsupported` fallback. Preserve streaming-over-legacy precedence, package-managed fallback/mutation checks, all field/container shapes, strict complete-document validation and numeric lexemes. Raw custom JSON never acquires financial exemptions. No mutable/global registry or Python bridge is introduced.
4. Validate original library-owned entity snapshot native text before ordinary `MarshalJSON` calls the encoder. Reuse that typed validation for existing entity-specific financial exports; preserve their complete raw shape, compact ordinary output, exact money, nil/empty/default semantics and literal IDs. A valid literal U+FFFD remains valid.
5. Do not relax credential diagnostics, the six opaque layouts/constructors and 28 raw getters, account construction defaults, strict JSON, or the privacy-safe deferred finite-streaming error marker. The deferred marker is not eager JSONable validity approval.
